# Phase 5：本地模拟诊断与审批演练

状态：采用（2026-10-08）。用户取消预发 Prometheus/Loki 和 Kubernetes 真实修复试点；本阶段所有证据与变更动作仅在本地模拟。此前未启用的 Prometheus/Loki 试验适配器已移除，原有 Mock 演示保持可用。

开发进展（2026-10-08）：四个含沙箱动作的场景已有操作后指标、日志和阈值；独立模拟验证器核对动作目标与结果，验证失败进入 `FAILED`，证据不足进入 `NEEDS_HUMAN`，通过才进入 `SIMULATION_COMPLETE`。五类模拟证据与验证轨迹携带场景内容摘要，便于追溯版本；未连接任何真实监控。

进度检查补充：审批前会核对所引用的模拟证据是否属于同一场景版本、内容摘要是否完整，以及当前版本是否仍可用；否则将审批标记为 `invalidated`、事件转 `NEEDS_HUMAN`，且不运行沙箱动作。浏览器中的失败状态文案同时区分了“模拟执行或验证失败”。已增加临时数据库的一键演示脚本与审计导出，浏览器回归 4 项通过。

后续补强：沙箱动作或验证器意外抛错时，审批结果与失败状态会持久化，轨迹只公开错误类型和所处阶段，不泄露底层异常详情；若动作已返回成功而验证器抛错，动作结果仍保留在审计中。页面审批按钮明确标注“模拟执行”。

历史状态展示：旧版 `RESOLVED` 不能直接解释为真实恢复。页面仅在存在通过的 `mock://` 验证轨迹时显示“模拟执行完成”；仅有沙箱动作时显示“历史模拟动作（未验证真实恢复）”；来源不明的历史结果显示“未核实真实恢复”。对应浏览器回归已覆盖这三种情况。

## 目标与非目标

目标：让每个故障场景都能在本地重复跑出一致的指标、日志、诊断建议、审批轨迹、沙箱动作和模拟验证结果；页面与导出审计明确标注“模拟”，不误报真实服务恢复。

不做：连接真实 Prometheus/Loki/CMDB/Kubernetes，不创建集群写凭证，不执行 Shell 或真实重启，不部署预发/生产自动修复。模型可以继续使用默认 Mock，或按现有配置使用本地模型；**模型是否真实不改变证据与动作均为模拟的性质**。

## 开发顺序

1. **模拟数据一致性**：为各场景固定时间线、指标、日志、服务拓扑与故障原因；所有五类只读工具返回 `mock://` 来源。将场景版本写入审计，防止修改场景后旧事件解释变化。
2. **审批演练**：保留申请人与审批人分离、拒绝、过期、重复点击和幂等检查；页面明确展示精确沙箱动作参数。当前请求头身份仅适合本地演示，不能被解释为真实身份认证。
3. **模拟执行与验证**：沙箱动作不影响任何真实服务。为场景定义独立的“模拟操作后状态”，由模拟验证器检查预期指标/日志变化；即使验证通过，也只进入 `SIMULATION_COMPLETE`，不进入 `RESOLVED`。执行失败或证据不足时保留原因并进入适当的失败/人工处理状态。
4. **本地可复现测试**：覆盖正常诊断、证据不足、审批通过/拒绝/过期、错误目标、重复提交、模拟动作失败和模拟验证失败；补齐 API 与浏览器 E2E，并提供一键演示脚本和可导出的审计样例。

## 状态和展示不变量

| 情况 | 页面与事件状态 |
| --- | --- |
| 仅完成诊断 | `DIAGNOSED`；明确“未执行修复” |
| 沙箱审批动作与模拟验证完成 | `SIMULATION_COMPLETE`；明确“非真实修复” |
| 拒绝/过期/证据不足 | `REJECTED` 或 `NEEDS_HUMAN`；无动作执行 |
| 模拟执行或验证失败 | `FAILED` 或 `NEEDS_HUMAN`；保留错误和审计轨迹 |
| 真实业务服务恢复 | 本阶段不判定；不得写入 `RESOLVED` |

验收门禁：全量测试、类型与 lint、关键浏览器流程通过；任意场景都不能访问真实监控或执行真实动作；审计中的每条证据都能追溯到模拟场景与版本。此计划不要求提供任何预发地址、监控标签或凭证。
